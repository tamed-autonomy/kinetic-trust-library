# KTP v2.1.0 Coverage Audit — Frozen Snapshot

This is a frozen coverage snapshot of KTP v2.1.0 at commit
15520035267546e1035aad7beea0cc3cf9ef8f2c. It changes only to correct a
factual or provenance error. Implementation progress is tracked separately in
docs/traceability/library-contracts.md.

- Normative source: `nmcitra/ktp-rfc`, tag `v2.1.0`, dereferenced commit
  `15520035267546e1035aad7beea0cc3cf9ef8f2c`.
- Library baseline: frozen pre-implementation Library snapshot.
- Review date: 2026-10-10.
- Progress: [maintained Library-contract matrix](../traceability/library-contracts.md).

The 81 stable requirement rows describe that frozen Library snapshot, not future
implementation. Their IDs are local trace keys, not upstream identifiers.
This count describes this frozen snapshot; it is not a permanent schema or an
automated test. This document is not a runtime registry, generated manifest,
product implementation checklist, or Basic/Standard/Full deployment or
certification conformance claim.

Only these dispositions are used:

- `implemented`: the narrowly described deterministic responsibility has evidence.
- `partial`: selected represented facts exist; the broader released contract does not.
- `missing Library contract`: no corresponding public Library contract in the frozen snapshot.
- `blocked by upstream ambiguity`: the immutable release does not settle one implementable contract.
- `intentionally product-owned`: an identified consuming product, service, provider, or operator owns it.

A public entry point identifies how a consumer reaches a contract; component
tests can exercise its calculation module directly. Tests below are focused
evidence, not substitutes for complete RFC coverage. A dash means no Library
implementation evidence is claimed for that row. Issue links are explanatory
tracking references from plan approval, not normative authority or assertions
about current issue status.
