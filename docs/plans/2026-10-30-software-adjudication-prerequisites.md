# Complete adjudication prerequisites in software consumption

The software contract already binds complete required prerequisite artifacts;
adjudication already supplies independently verified complete signed token bytes.
No new universal wire is needed to compose them.

The installed consumer now pins every selected native gate's ordered ID, exact
profile digest and strict boolean requirement in `adjudication_profiles`.
Required gates append `adjudication:<gate_id>` slots after readiness, any protected
carrier, grant and intent. Optional gates omit an artifact only when the actual
installed native policy independently says the gate is not required. A candidate
cannot remove, change or reorder expectations, or replace a boolean with a
numeric token. Required assessments must match those profiles/current time and
be satisfied; every complete unchanged signed token is digest-bound in order.

The signed software evaluation cannot precede any required token's issuance or
outlive its original expiration. Each use retains the native gate's shorter
current status deadline. Commit conditions include actual gate/profile/token
identities and current authenticated gate state. Approval remains a prerequisite,
never extra capacity, a standing contribution or execution permission.

Continuing checkpoints reuse retained signed tokens by default and rerun their
actual native verification against current authority/possession/grant/evidence/
epoch/status. Explicit replacements can be supplied; they require a new matching
software decision. Explicit `None`/empty token collections reach native missing-
token checks instead of silently succeeding. Original token expiry and current
key/status revocation withhold use. No cached approval or re-signing extends it.

Real signed single/multiple/optional gate integration checks profile pinning,
omission/substitution/order/duplicate rejection, replacement binding, issuance
ordering, original expiry and current revocation. Current-source/key-role and
operational registry facts are modeled provider boundaries, not deployment proof.
Relational/reissue, repair, ambient, federation and normative-demand artifact
combinations remain explicitly rejected by this selected software adapter.
