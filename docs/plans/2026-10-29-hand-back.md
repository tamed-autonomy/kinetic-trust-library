Execute inline using the existing TDD/execution/verification workflow.
Source: `17f37b772eac8b2f84248c1912f3aeb3f5fa26d1`,
`specifications/hand-back.md`, exact schema and 73 retained source cases.

1. Validate raw hand-back wire against the pinned closed schema. Resolve actual
   subject/action/consequence/reason/recipient/recourse/repair against an installed
   authenticated registered template, scope and clock. No orphan stop becomes a
   domain value; protocol errors return recording/routing obligations.
2. Verify the sealed ciphertext hash and recipient key, authenticated complete
   context manifest and registered redaction tier, with no plaintext or decryption
   key returned by the library. Source owns actual envelope/key/content truth.
3. Keep delivery state separate from denial: saturated/unreachable/unconfirmed
   delivery parks, never restores clearance. Service owns durable escrow,
   actual attempts, retries, acknowledgment and escalation. A claimed delivery
   must agree with actual capacity-aware delivery evidence.
4. Add typed non-Clear/Clear validation, routine lease expiry versus adverse
   environment failure, exact lease/intent/class and authority bindings, declared
   hysteresis and relational repair/single-use checks. Compose with native results.
5. Add broader hostile-vector coverage, supplier review, full regression and
   installed-package verification, document exact remaining dependencies and push
   checkpoints. No PR, merge or release.

The private adapter schema must not be presented as an RFC lease/clearance wire.
Bootstrap refusal without a template and agent-visible reason wording contain
draft ambiguities (HB-02-002 and HB-11-004 versus §4.4); record them explicitly.
Production key custody, independent recourse, live human capacity, durable replay,
audit and delivery are Service/deployment evidence, not Library completion claims.
