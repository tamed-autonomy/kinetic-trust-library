# Continuing software consumption under a pinned current-use graph

`InstalledSoftwareCheckpointVerifier` pins the exact consumer and existing-
reservation verifier/profile before use. Per-call inputs cannot select those
expectations. It requires the same retained actual operation and a healthy
nondecreasing clock, revalidates the original reserved invocation through the
current native graph, and reruns software/Clearance checks with retained
management and software continuity. Optional replacement readiness artifacts
must be provided together and independently satisfy their installed contract;
changing them also requires a matching software prerequisite binding.

The consumer retains its last successful native checkpoint across unrelated
denials, just as it retains software history and management. This retains only
provenance for a fresh recheck: a denied result never becomes consumable through
that retained data. Actual current proof/Root/readiness/boundary and reservation
checks still run before recovery. Ordinary reserve/acceptance is never repeated.

Signed-artifact lifetime is bounded by original ordinary proof, required signed
readiness/attestation, geometry profile/carrier, grant, software observation and
signing-key deadlines. A current-state query/recheck deadline can shorten each
use without forcing re-signing an otherwise unchanged still-live decision.
Every use ends at the shortest current native/Clearance/software/checkpoint
deadline. Fresh queries cannot refresh underlying observation times or extend
original artifact validity. No new proof, grant or request ID is manufactured.

Conditional commit conditions additionally pin the checkpoint profile and exact
authenticated current protected original reservation. These are Service
conditions; actual atomic revalidation, continuing-operation scheduling,
interruption and enforcement remain Service responsibilities. No callback,
background timer, queue, target effect or release evidence is claimed here.

The real-signed integration reuses the identical software artifact, ordinary
proof and original observations at the next checkpoint, rechecks current Roots,
handles a temporary readiness denial without losing prior checkpoints, rejects
another installed checkpoint instance, and stops at the exact original
observation deadline. Operational Sources are modeled, not deployed providers.
