# Registered hand-back for current software permit-condition loss

Hand-back proposal `5ea926338cb69a80fa9cf6a816334891acf9bed5` Sections 3
and 4.1 require the registered return path when a required permit condition
fails. Software proposal `8dda717a51818a5e9ef00e36898ddae6af890230`
requires withholding when repair/supervision establishment is lost and preserves
independent constraints, current invalidation and unresolved restrictions.

Failed software assessments now expose a hand-back obligation when current
authenticated software conditions are unavailable/restricted, availability is
lost, or a verified restriction excludes the actual operation. Observed decision
bytes are retained as audit input, separate from verified signed decision bytes;
this retention confers no authority. Invalid candidate signatures/bindings alone
do not fabricate an authenticated local-condition loss.

`InstalledSoftwareStopResolver` pins a current-use checkpoint profile. It reruns
that graph and requires actual current failure, current managed membership and
the same active original grant and registered template. The immutable cause
binds current profiles, operation/proof/geometry, grant/template, software state/
frame, availability/restrictions and candidate provenance. Its preparation Source
must genuinely seal the cause and durably register the stop, not acknowledge an
intention to do so. The shared registered-stop validator then rereads actual
current clearance, requiring the exact original prepared `Exceeded` hand-back,
unchanged grant/intent/relation/admission and registered system recourse branch.
Actual delivery, interruption, persistence and retry remain Service work.

The preparation DTO is the same exact internal authenticated cause/anchor/wire/
evidence contract used by native stop resolution, exposed here as
`PreparedSoftwareStop`. It is not a new RFC wire schema. Existing native
adjudication/readiness stops share the checked post-registration path; readiness
stops now also accept fresh unexpired `RB_CURRENT` failures. Repeated resolution
after a stop is already registered uses ordinary typed non-clearance rather than
manufacturing another stop. Genuine Source IO failure still propagates; it does
not become an invented authenticated condition or successful hand-back.

The signed integration checks repair and supervision loss, exact typed return
path, and rejection of acknowledgment without registration, substituted cause,
and grant revocation during preparation. Modeled operational Sources establish
deterministic Library behavior, not real delivery or durable deployment proof.
