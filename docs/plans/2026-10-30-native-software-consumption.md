# Native software consumption under the optional proposal

Continue the approved implementation with a deliberately named, bounded private
adapter: `native-duration-software-consumption-v1`. It composes an actual current
native conditional Clear with current management, structural authority audit,
installed software evidence and independent classical sidecar verification.
Deployment, zone, algorithms and every installed profile digest must match.

The adapter supports duration grants and the ordinary readiness/boundary path.
Relational/reissue and supplemental adjudication, repair, ambient, federation
and normative-demand prerequisite families are rejected at installation until
their complete original artifacts have an explicit binding contract here. This
does not change those families' independent native implementations or enable a
software selector on the ordinary native verifier.

The installed prerequisite order is exactly readiness, grant, principal intent.
Readiness uses its complete native-verified canonical signed decision. The named
`authenticated-vendor-grant-intent-v1` Source contract supplies complete original
signed vendor grant/intent bytes and authenticated semantic projections, which
must equal the independently current native clearance facts. No standard vendor
grant wire format is invented. Actual signature authentication and projection
truth remain the provider's responsibility. The principal's intent is checked
at mint time under the native lease contract; it is not a second currently-live
permission token. The grant remains independently current and bounds validity.

The consumer binds the unchanged complete ordinary proof, actual complete
request binding, ordered original evidence, current epoch and exact required
prerequisites. It rejects an evaluation predating its observations/readiness/
grant, a lifetime exceeding any applicable input or key deadline, A below the
native demand, E above the native capacity, substituted calibrated assessments,
false availability assertions, raised ceilings and lowered supervision floors.
The existing native constraints remain independently binding. A tighter software
ceiling that excludes the actual operation requires a newly evaluated operation.

The optional margin is accepted only when its represented JSON decimal equals
the exact computed rational margin. No rounding rule is invented for repeating
or high-precision margins: omit the optional wire margin where it cannot be
represented exactly. The audit projection still retains the derived local
margin. This selected adapter's observation/checkpoint times use integer Unix
seconds and do not claim sub-second capability.

The sealed result records current graph assessments and conditional use with
`action_permitted = false`. Its commit conditions retain the native/software
constraints, current clearance/management/authority/readiness/boundary facts,
key/evidence identities, protected epoch/history frame and earliest checkpoint.
The Service must revalidate the complete native graph, including live Roots,
identity/replay and ingress, and atomically fence all applicable current state
before effects. A JSON condition object proves neither atomicity nor effects,
and does not implement queues, budgets or #139 evidence.

Validation uses the real signed ordinary proof/readiness native fixture and
modeled authenticated management, grant and observation Sources. These checks
are deterministic integration evidence, not a production-provider deployment or
a conformance claim for a final RFC release.
