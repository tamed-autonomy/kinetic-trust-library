# Separate software-substrate consumption profile

Source: optional proposal `8dda717a51818a5e9ef00e36898ddae6af890230`,
`software-substrate-execution-profile.md`, decision schema and 38 modeled/26
schema cases. This draft is not adopted and has no independent release number.
The existing ordinary-native profile continues rejecting execution-profile
substitution. New software consumption must have its own explicit interface;
ordinary geometry/readiness is a prerequisite, not a substitute for its contract.

Implementation order:

1. Retain exact source/schema/vector bytes and pin provenance. Add pure software
   magnitude/ceiling and supervision restriction composition, required repair/
   supervision availability and native comparable-scale capacity vetoes. These
   helpers grant no action and do not authenticate observations or decisions.
2. Validate complete strict decision shape and integer representations, real
   purpose-separated signatures under installed issuer keys and exact complete
   proof/request/profile/policy/evidence/prerequisite bindings.
3. Install actual invocation/evidence/current-epoch/status and restriction-history
   sources, independently recheck current native prerequisites, availability,
   freshness, original observation times and earliest validity. Preserve native
   constraints alongside the software magnitudes; none may be silently dropped.
4. Add explicit candidate issuance/consumption interfaces only after those
   checks. No target effects, queues, budgets, replay or #139 confirmations are
   implied. Calibration, physical measurement truth, actual destination identity,
   custody, protected persistence and effect fencing remain provider/Service work.

For each concrete slice: meaningful source/negative tests, review, regression,
installed wheel and checkpoint push; no PR, merge, release or conformance claim.
Modeled trusted-fixture flags are test notation and cannot be accepted as a
production replacement for signatures or current state.

First implemented stages: exact local schema plus strict JCS/control tokens,
non-widening native-scale restriction arithmetic, and an independently installed
`software-decision-es256-ed25519-v1` signature profile. Its exact curves and
purpose are fixed; it is not a conformance-level declaration or threshold/hybrid
profile. Original complete decision content, installed profile/policy, issuer
role/zone/revocation and key/artifact time are bound. Real P-256/Ed25519 tests
reject substitution, wrong purpose, changed policy, revoked/expired keys and
high-S ECDSA. Signature assessments explicitly leave complete consumption
unverified and grant no action. Full current-evidence/prerequisite composition
remains the next slice; these stages do not enable ordinary-native fallback.
