## Current dependency order

1. Complete readiness/authorization integration around the native Core-to-proof-to-record/carrier path. Native record production and carrier issuance now exist, with authenticated grant/prior boundaries, restrictive unknowns and source bindings. They establish evaluation records, not current readiness or permission.
2. Finish remaining proof arithmetic/source invariants, real root/witness fixture verification, current-use evidence refresh and nested ingress profiles. The complete proof verifier and signed native Core-to-proof path now exist.
3. Compose accepted proof, actual request, durable replay boundary, prior supervision, grants/readiness and Decision Geometry into one immutable evaluation result, then replace the public v2 APIs. Product adapters retain persistence, source access and execution ownership.
4. Run the Library and Service suites against the final RFC tag, update the RFC pin and package version, and exercise installed-wheel examples.

Validation results belong to the individual pushed checkpoints; the latest count is not itself evidence of production source truth or complete RFC coverage. The package remains version 2.1.0 pending the deliberate public v3 cutover.

Until steps 1–3 are implemented, an RFC freeze would still leave substantial Library work. The target is to finish those steps on this branch while treating proposal-specific edges as replaceable. The final tag should then require a source diff review, localized changes, fixture refresh, and release verification.
