# Resolve a new required adjudication failure through its registered return path

Continue the approved runtime hand-back work. Select one precise existing
failure: a required native adjudication gate is unsatisfied. This is an adverse
permit-condition exit, not proof/lease expiry and not a principal revocation.
The installed resolver must first establish current managed classification,
an active actual grant, and the exact original registered template.

Derive an immutable cause from the actual native result/request/proof/geometry
and current clearance state. An installed preparation adapter owns full-context
sealing, actual append/registration and delivery work; it must return that exact
cause, its stop anchor, original hand-back bytes and authenticated evidence.
Re-evaluate the existing full clearance graph against the newly current registry
and accept only an `Exceeded` that carries those exact bytes and anchor, with
the same active grant and the registered system recourse branch. Preserve all
current management, sealed context, template, lease and hysteresis checks.

This is a private adapter protocol and a deliberately bounded runtime family.
No generic native reason-class mapping, human disclosure policy, grant renewal,
effect execution or success of actual delivery is invented. Adapter outages or
missing/mismatched current records fail closed. Test real native failure and
existing sealed hand-back fixtures, review, full regression, installed wheel,
commit and push; continue other implementable work.

Implemented resolver retains the exact cause and preparation evidence, rechecks
the original active grant and admission after preparation, and rejects changed
intent, grant, relation, admission or system recourse origin. An acknowledgment
with no current matching stop fails, as does substituted cause or a revoked
grant. Preparation outages propagate. A parked hand-back remains parked and its
delivery effort remains owed; this method does not claim transport completion.

The method resolves new stops only. If the current registry already contains an
adverse stop, callers use the existing clearance path rather than creating
another event. Production preparation must make cause/stop registration durable
and idempotent and coordinate it with actual encryption and delivery. This
wrapper validates the declared original cause and current record; it does not
prove a storage append, inspect recipient plaintext or manufacture a receipt.
